# Laravel 12 + Filament 5 Security & Performance Enhancement Plan

**Project:** `backend/` (Serv5 Backend API & Admin/User Panels)  
**Stack:** PHP 8.3.0 · Laravel 12.61.1 · Filament 5.6.6 · Livewire 4.3.1 · Filament Shield 4.2.0 · Spatie Permission 6.25.0 · Sanctum 4.3.2 · MySQL  
**Audit Date:** 2026-10-31  
**Audit Mode:** Read-Only Static Analysis, Dependency Audit, & Local Read-Only Benchmarking

---

## 1. Executive Summary

### Overall Scores
- **Security Score:** **4.5 / 10** — Strong foundational primitives exist (Cloudflare Turnstile middleware, custom CSP/HSTS `SecurityHeaders` middleware, encrypted `AiCredential` token storage, DOM-based `GeneratedHtmlSanitizer`, and Spatie/Shield model policies on all 19 Filament resources), but **two critical privilege-escalation / authentication-bypass vulnerabilities** in the `/user` Filament panel and WhatsApp OTP registration flow, an IDOR on private quotation file downloads, and **13 Composer + 10 NPM vulnerability advisories** require immediate remediation before production traffic.
- **Performance Score:** **5.5 / 10** — Several public endpoints use `Cache::remember`, eager loading, and WebP conversion, but **optional pagination defaults to unbounded `->get()` dumps** (up to **4.08 MB** on `/api/v1/careers` and **795.8 KB** on `/api/v1/blog`), `CACHE_STORE=database` + database rate-limiting executes **7 SQL queries (including `SELECT ... FOR UPDATE` row locks) on every warm GET request**, model `saved`/`deleted` hooks fail to invalidate list caches, and `Cache::remember` serializes unresolved `AnonymousResourceCollection` / Eloquent instances instead of resolved arrays.

### Top 5 Risks
1. **[SEC-01 | Critical] Customer Panel (`/user`) Exposes All 17 Admin CMS & AI Builder Pages Without Authorization (`app/Providers/Filament/UserPanelProvider.php:133-134`, `app/Filament/Pages/*.php`)**: `UserPanelProvider` auto-discovers `app/Filament/Pages`. Unlike Resources (which enforce policies), none of the 17 custom Filament Pages implement `canAccess()` or Shield's `HasPageShield` trait (`config/filament-shield.php:249` has `'discover_all_pages' => false`). Any authenticated customer (`read_only` role) in `/user` can open `/user/manage-home-page`, `/user/manage-seo-settings`, `/user/ai-generation-dashboard`, `/user/ai-page-builder`, etc., overwrite site-wide CMS settings, or dispatch paid AI generation jobs.
2. **[SEC-02 | Critical] Livewire Public Properties Leak Plaintext WhatsApp OTP & Password to the Browser (`app/Filament/Pages/Auth/RegisterWithOtp.php:22-24, 82-99, 125-127`)**: `public $tempData = []` stores the plaintext 6-digit `otp` and plaintext `password` without `#[Locked]`. Livewire serializes public properties into the browser wire snapshot payload, exposing the OTP in the HTTP response and allowing an attacker to mutate `tempData['otp']` or `tempData['phone']` client-side to bypass verification completely.
3. **[SEC-03 | High] Broken Access Control (IDOR) on Private Quotation File Downloads (`routes/web.php:16-39`)**: `GET /admin/quotation-files/{quotation}/{filename}` only enforces `middleware(['web', 'auth'])` without checking `$request->user()->can('view', $quotation)` or `hasRole('super_admin')`. Any regular `/user` account can download private quotation attachments belonging to other customers.
4. **[SEC-04 | High] Known Critical/High CVEs in Locked Dependencies (`composer.lock`, `package-lock.json`)**: `laravel/framework` `v12.61.1` is affected by **Critical** `CVE-2026-114509` (TokenGuard auth bypass via non-string credentials) and `CVE-2026-114508`; `filament/filament` `v5.6.6` is affected by **High** `CVE-2026-77567` (MFA bypass when recovery codes are enabled); `livewire/livewire` `v4.3.1` is affected by `GHSA-mhf7-xp6r-6qrc` (`#[Authorize]` bypass) and `CVE-2026-81887` (DOM XSS).
5. **[PERF-01 / PERF-02 | Critical/High] Unbounded `->get()` Payloads & Uncached `/api/v1/careers` (`app/Http/Controllers/Api/CareerController.php:16-56`, `BlogController.php:57`, `ProductController.php:45`)**: `GET /api/v1/careers` has no caching and defaults to `->get()` when `?page=` is omitted, returning **4.08 MB** (`4,083,483 B`), a **66.9 ms** SQL scan, and an **8 MB** PHP memory spike on every request (~453 ms). Similarly, `/api/v1/blog` (795.8 KB) and `/api/v1/products` (490.2 KB) dump full tables when `?page=` is omitted and store multi-hundred-kilobyte blobs in the MySQL `cache` table.

### Top 5 Quick Wins
1. **Lock down `/user` panel page discovery & `/admin/quotation-files` route (`< 30 mins`)**: Remove `->discoverPages(in: app_path('Filament/Pages'))` from `UserPanelProvider.php:134`, enable `HasPageShield` on admin pages, and add `->can('view', 'quotation')` to `routes/web.php:16`.
2. **Enforce mandatory bounded pagination (`paginate(min($perPage, 50))`) + `Cache::remember` on `CareerController`, `BlogController`, `ProductController`, `PortfolioController`, `FaqController`, `PageController` (`< 1 hour`)**: Cuts `/api/v1/careers` payload from **4.08 MB to ~15 KB** and `/api/v1/blog` from **795.8 KB to ~25 KB**.
3. **Move OTP state out of public Livewire properties into server-side `Cache`/`Session` with `random_int()` & `Hash::check()` (`< 1 hour`)**: Eliminates the critical OTP disclosure and client-side tampering vulnerability in `RegisterWithOtp.php`.
4. **Run `composer update` and `npm audit fix` (`< 30 mins`)**: Patches all 13 Composer advisories (`laravel/framework >= 12.69.0`, `filament/filament >= 5.11.0`, `livewire/livewire >= 4.4.8`) and 10 NPM advisories.
5. **Switch `Cache::remember` closures to cache `->resolve()` arrays and switch `CACHE_STORE` / rate-limiter to Redis (or APCu/array in local) (`< 1 hour`)**: Eliminates 6–7 MySQL queries (`SELECT ... FOR UPDATE` locks) on every warm API request and avoids re-running `JsonResource::toArray()` on cached Eloquent models.

Evaluated via `php artisan about --json` (local environment state), `.env.example`, and `config/*.php`.
- **Live POST endpoint mutations, live Cloudflare Turnstile challenge verification, live WhatsApp OTP gateway delivery (`services.whatsapp`), and live external LLM calls (OpenAI / Gemini / DeepSeek)**: **Not verified** via live network calls in strict compliance with *"READ-ONLY audit. Do NOT change any application code, config, migrations, or the database"* and *"Do NOT call POST endpoints or flood the server"*. Audited via static code analysis and test suite inspection.
- **Production host infrastructure (Nginx/Apache vhost configs, PHP-FPM pool settings, OPcache/JIT ini flags in production, Supervisor worker configs, TLS termination, and cron/backup daemons)**: **Not verified** because infrastructure manifests (`nginx.conf`, `supervisord.conf`, `Dockerfile`, `docker-compose.yml`) are not stored in the repository.

### Root Cause Analysis of the 5 Slowest Endpoints

1. **`GET /api/v1/careers` (452.0 ms cold / 453.2 ms warm avg · 4.08 MB payload · +8.0 MB RAM)**
   - **Cause 1 (`CareerController.php:16-56`)**: No `Cache::remember()` wrapper exists, so warm requests are just as slow as cold requests.
   - **Cause 2 (`CareerController.php:54`)**: When `?page=` is not passed, `$query->get()` loads every active career row and transforms all long-text fields (`description`, `requirements`, `benefits`) into a **4.08 MB JSON response**.
   - **Cause 3 (`CareerController.php:41 & 55`)**: Runs `SELECT DISTINCT department FROM careers WHERE is_active = 1 AND department IS NOT NULL` on every request, then throws `$departments` away at `line 55` when `$page` is omitted.
2. **`GET /api/v1/blog` (446.3 ms cold / 229.3 ms warm avg · 795.8 KB payload · +10.0 MB RAM on cold)**
   - **Cause 1 (`BlogController.php:57`)**: When `?page=` is omitted, `$query->get()` loads all published blog posts (`33.32 ms` SQL).
   - **Cause 2 (`PostResource.php:43` & `PostContentFormatter.php:21-32`)**: `PostResource::toArray()` calls `PostContentFormatter::format($this->content)` for every post in the list, parsing and normalizing full article HTML and allocating **10.0 MB** of PHP memory.
   - **Cause 3 (`BlogController.php:23`)**: Writing the resulting **795.8 KB** array into the MySQL `cache` table takes **26.60 ms** (`INSERT`) and **13.52 ms** (`SELECT` on warm hits).
